# Three-minute local demo

## Before recording

Start the [local browser stack](RUNBOOK.md#review-bids-in-the-browser) with a fresh GigSim
mini-world database and a fresh web checkpoint. Keep those files separate from your usual work.
Use `MARKETPLACE_MODE=gigsim`, `GIGSIM_CLIENT_MODE=rules`, `GIGSIM_ERROR_RATE=0`, and
`GIGSIM_LATENCY_MS_MAX=0` for the recording. Open `http://127.0.0.1:3000` and prepare tabs for
the four views in the table below. Run the synthetic interview setup before recording so the
client message is already waiting.

## Prepare the synthetic interview

This setup submits a hand-written synthetic forecasting proposal using the local simulator API.
It reliably produces an interview request when run against a fresh mini-world before any other
proposals. Use the same local `GIGSIM_ADMIN_TOKEN` that the simulator was started with. Keep the
setup terminal and credentials out of the recording.

```powershell
$demoSim = 'http://127.0.0.1:8081'
if (!$env:GIGSIM_ADMIN_TOKEN) { throw 'Set the local simulator admin token first.' }
$demoAdmin = @{ 'X-Admin-Token' = $env:GIGSIM_ADMIN_TOKEN }
$demoTokenMap = if ($env:GIGSIM_API_TOKENS) {
    $env:GIGSIM_API_TOKENS
} else {
    'dev-token-ai:persona_ai_ml'
}
$demoAccount = $demoTokenMap -split ',' | ForEach-Object { $_.Trim() } |
    Where-Object { $_ -match ':persona_ai_ml$' } | Select-Object -First 1
if (!$demoAccount) { throw 'Configure the synthetic AI/ML persona first.' }
$demoBearer = 'Bearer ' + ($demoAccount -split ':', 2)[0]

Invoke-RestMethod "$demoSim/admin/tick" -Method Post -Headers $demoAdmin `
    -ContentType 'application/json' -Body '{"n":2}' | Out-Null

$demoDraft = Invoke-RestMethod "$demoSim/proposals" -Method Post `
    -Headers @{ Authorization = $demoBearer; 'Idempotency-Key' = 'demo:forecast:draft:v1' } `
    -ContentType 'application/json' -Body (@{
        job_id = 'job_later_ml'
        bid_amount = 2500
        bid_type = 'fixed'
        screening_answers = @()
        cover_letter = 'For weekly demand forecasting across 300 SKUs, I built the Python machine learning workflow in a comparable synthetic case study. I built the Python forecasting pipeline to align weekly demand and SKU history before training. I shipped a machine learning case study that compared seasonal baselines against supervised models using rolling validation windows. My Python case study documented validation for weekly demand, errors by SKU, and a reproducible forecast handover.'
    } | ConvertTo-Json -Depth 4 -Compress)

Invoke-RestMethod "$demoSim/proposals/$($demoDraft.proposal_id)/submit" -Method Post `
    -Headers @{ Authorization = $demoBearer; 'Idempotency-Key' = 'demo:forecast:submit:v1' } |
    Out-Null
Invoke-RestMethod "$demoSim/admin/tick" -Method Post -Headers $demoAdmin `
    -ContentType 'application/json' -Body '{"n":4}' | Out-Null

$demoThread = (Invoke-RestMethod "$demoSim/threads" -Headers @{ Authorization = $demoBearer }) |
    Where-Object { $_.job_id -eq 'job_later_ml' } | Select-Object -First 1
if (!$demoThread) { throw 'The expected synthetic interview did not arrive.' }
$demoThread | Select-Object job_title, stage
```

The Playwright workflow reproduces this setup against an isolated simulator and checks that a
reloaded review sends one exact edited reply. After advancing four more simulator ticks, the
test drafts a reply to the next turn and verifies that rejecting it with a reason sends nothing.
